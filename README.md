# qnx-rt-probe

A Linux CLI that measures **real-time message-passing latency on QNX 8.0
in QEMU** — and reports it as percentiles with a pass/fail verdict.

Built for the **QNX Global Hackathon 2026** (Devpost, $50,000), category
**Developer Tooling & Host Tools**. The demo exercises QNX-specific
technology the $3,500 "Best Use of QNX Tech" bonus rewards: native
message passing (`MsgSend`/`MsgReceive`) and priority scheduling.

## Why this is different

Most QNX tooling automates build + boot. This tool does the next step:
it **quantifies** the real-time behaviour. A high-priority sender and a
low-priority receiver exchange a 64-byte message under CPU load, and the
tool reports round-trip latency (p50/p95/p99), jitter (max + p99), and a
PASS/FAIL verdict against thresholds. If your priority design does not
hold up under load, the numbers say so.

## Quickstart (host, no SDP needed)

```sh
make
./qrtp bench --host            # 10,000 iterations, 1 load thread
./qrtp report results/<latest>.json
```

Or the wrapper: `scripts/run-host.sh`.

## Commands

| Command | What it does |
|---|---|
| `qrtp doctor` | Environment check: gcc, QEMU, `qcc`, `~/qnx800`, QSTI image |
| `qrtp bench --host` | Host benchmark (see options below) |
| `qrtp report <file>` | Re-print a report JSON as a table |
| `qrtp build` | STUB: cross-compile the QNX demo (needs `qcc`) |
| `qrtp boot [--image P]` | STUB: boot the QSTI image in QEMU |
| `qrtp run` | STUB: full pipeline (blocked on the SDP) |

`qrtp bench --host` options: `--iterations N` (default 10000),
`--warmup W` (default 500, excluded), `--load N` (default 1),
`--out FILE` (default `results/<timestamp>.json`),
`--p50-us X` (default 100), `--p99-us Y` (default 500).
Verdict is PASS only when p50 ≤ threshold AND p99 ≤ threshold.

## Report format

JSON (one file per run) plus a human table on stdout. Fields: `tool`,
`tool_version`, `transport` (`posix-socketpair` on host, `qnx-msgsend`
in the guest), `host`/`qnx` flags, `iterations`, `warmup`,
`load_threads`, `priority_elevated` (true only if SCHED_FIFO was
actually applied — on an unprivileged host it falls back to SCHED_OTHER
and says so), `thresholds_us` (with `source: "host-default"` — these
are host-calibration placeholders, not guest thresholds), `stats`
(count/min/max/mean/stddev/p50/p95/p99/jitter_max/jitter_p99, all in
µs), `verdict`, `generated_at`. A real example from a host run:
`examples/host-report-example.json` (generated by `make test`).

## Layout

- `src/main.c` — CLI; `src/bench.{h,c}` — measurement core;
  `src/stats.{h,c}` — percentiles/jitter; `src/report.{h,c}` — JSON +
  table; `src/transport.h` — transport interface;
  `src/transport_posix.c` — socketpair host transport;
  `src/transport_qnx.c`, `src/qnx_demo.c` — QNX guest code (qcc only).
- `scripts/run-qemu.sh` — QEMU orchestration (ready for M1);
  `scripts/run-host.sh` — host wrapper.
- `tests/` — unit test (`test_stats.c`) + smoke test (`test_bench.sh`).
- `docs/CODELAB.md` — draft codelab (Best Codelab bonus).
